# AGENTS.md

This file gives AI coding agents (Claude Code, Codex, Cursor, etc.) context on how to work in this repository.

## Project Overview

A Deno/Hono implementation of the LTI 1.3 Advantage specification written in TypeScript,
exporting a LTIKit class for handling LTI launches, authentication, and Advantage services (Deep
Linking, AGS and NRPS).

## Tech Stack

- **Runtime:** Deno
- **Database:** Deno KV
- **Framework:** Hono
- **Language:** TypeScript

## Commands

```bash
# Run tests
deno task test

# Type-check
deno check mod.ts

# Format code
deno fmt

# Lint code
deno lint
```

## Project Structure

```
.
├── mod.ts                # Module entry point, provides the main LTIKit export alongside some types
├── docs                  # Ignore this folder. It is generated by `deno doc --html mod.ts`
├── src/constants.ts      # Shared constants
├── src/crypto.ts         # Crypto helper functions
├── src/lti-kit.ts        # The main class export of this library. Clients make api calls against a LTIKit instance.
├── src/messages.ts       # LTI 1.3 message strings as constants
├── src/types.ts          # Shared types
├── src/auth/             # Methods for handling OIDC and access token creation and validation. Makes heavy use of @panva/jose
├── src/middleware/       # Custom Hono middleware
├── src/routes/           # Provided LTI route handlers
├── src/services/         # LTI 1.3 Advantage service implementations
├── src/storage/          # A class based API which uses Deno KV for persistence
├── src/utils/            # Utility modules
├── deno.json             # Deno config, tasks, and import map
└── deno.lock             # Lockfile
```

## Conventions

- Use Deno's built-in tooling (`deno fmt`, `deno lint`) rather than adding Prettier/ESLint.
- Prefer `npm:` or `jsr:` specifiers over a `node_modules`-based setup; keep imports mapped in `deno.json`.
- Use Hono's built-in validators (e.g. `@hono/zod-validator`) for request validation rather than hand-rolled checks.
- Group routes with `Hono` sub-app instances (`app.route('/users', usersRoute)`) instead of one giant file.
- Add any Deno KV access to `src/storage/denokv-storage.ts`. Don't sprinkle Deno KV calls throughout the codebase.
- Use explicit types for request/response shapes; avoid `any`.

## Testing

- Use the `test` task from `deno.json`. `deno task test`
- Test files live alongside source as `*_test.ts`.
- Prefer Hono's `app.request()` for testing routes without spinning up a real server.

## Notes for Agents

- This project does not use Node.js or npm as the primary runtime — don't suggest `npm install`, `package.json` scripts, or Node-specific APIs (`fs`, `path` from `node:` without the specifier) unless explicitly needed via `npm:` compat.
- Always check `deno.json` for existing tasks and import aliases before adding new dependencies.
- Prefer standard library modules from `jsr:@std/*` where applicable.
